# cc-vision —— 借 MiniMax M3 看图

当前模型(DeepSeek 等纯文本中转)收不了图片时,用本 skill 把图片交给 **MiniMax-M3**
(MiniMax 官方支持图片的视觉模型)分析,拿回描述后再由你继续处理。这是**工具调用**,不是换模型。

## 前提:`MINIMAX_API_KEY`

容器内需有 `MINIMAX_API_KEY` 环境变量(cca 用 `--env-file` 注入)。**没有就提示用户**:
在宿主机 `~/.config/cca/common.env` 加一行 `MINIMAX_API_KEY=<你的MiniMaxKey>`
(common.env 对所有 profile 生效),然后重启 `cca`。

## 步骤

1. **确定要看的图片**。用户可能给了路径(`@` 引用)或让你自己找文件;先确认文件存在、
   格式是 JPEG/PNG/GIF/WEBP、单张 ≤ 10MB。不满足就直接说明,别硬调。

2. **构造给 MiniMax 的问题**。把"用户真正想知道的"写清楚,别只写"描述图片":
   - 图里是代码 → 要求 **逐字转写**,并附上相关上下文(文件路径、语言);
   - 图里是报错 → 要求 **原样摘录** 错误信息;
   - 一般看图 → "请详细描述图片内容,并回答:...",把用户的疑问拼进去。

3. **调用 helper 脚本**:

   ```bash
   python3 ~/.claude/skills/cc-vision/minimax_vision.py '<图片路径>' '<你的问题>'
   ```

   - 路径含空格要加引号。
   - 脚本把图片 base64 发给 MiniMax-M3,stdout 即模型回答;失败会以非零退出码退出,
     stderr 是原因(缺 KEY / 超大小 / 格式不支持 / API 报错)。

4. **消化给用户**。把原始回答整理成用户能直接用的结果:代码转写就原样给出、
   报错就指出关键行、图片内容就概括要点。**不要只甩原文**。

## 注意

- **隐私**:图片会 base64 后发给 MiniMax 官方接口。敏感图先提示用户确认。
- **一次一张**:用户给多张图时逐张调用,再汇总;脚本不支持多图。
- **失败排查**:
  - 缺 KEY → 提示去 `common.env` 加并重启 `cca`;
  - 图片过大 → 让用户压缩后再试;
  - API 报错 → 把 stderr 完整贴给用户,别自己吞掉。
